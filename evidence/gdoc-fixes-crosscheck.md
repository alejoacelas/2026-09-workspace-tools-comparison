# Bug transfer audit: gdoc fixes tested against Workspace MCP

The most useful transferred findings are a **credential-file permission bug already fixed in gdoc but still reproducible in Workspace**, and **lossy document rebuilds that both pinned releases permit**. Workspace also loses list nesting in its native Markdown writer, while gdoc emits indentation but also flattened the later live fixture (see the controlled follow-up below). Its plain replacement route avoids several gdoc-specific problems by delegating matching and replacement to Google.

Scope: public gdoc PRs inspected on 2026-09-12; gdoc `dbfa4c34bfa699ee8dd9839da85eea1fac177d44` (0.21.0), Workspace `54b1c56f7f9912ce32681460d7ca38f9c2a37564` (1.26.0). This is a targeted 12-family transfer audit, not a vulnerability census. PR status describes the public repository at inspection time. Open proposals are **not credited as released fixes**. In particular, #62 and #65 are alternative open rebuild protections, not two installed layers of protection.

Reproduce with:

```sh
~/.local/share/uv/tools/workspace-mcp/bin/python probes/gdoc-fixes-crosscheck.py
```

The [probe](../probes/gdoc-fixes-crosscheck.py) uses upstream code, mock Google responses, and temporary dummy credentials. [Captured results](gdoc-fixes-crosscheck-results.json) include the generated requests. It never contacts or modifies Google. Passing assertions mean the pinned behavior was reproduced, including defects; they do not mean the behavior is correct. The temporary file test removes only its own disposable synthetic fixture on exit. Public PR metadata is preserved in [gdoc-prs.json](gdoc-prs.json).

## Findings that change tool choice

### A merged gdoc fix transfers directly to Workspace's credential store

Workspace's [`store_credential`](https://github.com/taylorwilsdon/google_workspace_mcp/blob/54b1c56f7f9912ce32681460d7ca38f9c2a37564/auth/credential_store.py#L220) opens the existing file with `O_WRONLY | O_CREAT | O_TRUNC` and mode `0600`. The mode is used only when creating the file. A pre-existing loose mode survives the refresh/save operation. gdoc's [`_write_private`](https://github.com/LucaDeLeo/gdoc/blob/dbfa4c34bfa699ee8dd9839da85eea1fac177d44/gdoc/auth.py#L247) writes a fresh private file and atomically replaces the old one. The same offline test distinguishes them without handling any real secret. Practical exposure depends on directory traversal permissions too: a private parent directory can prevent other users from reaching a loose file. This finding does not imply the user's current installation is exposed.

### “Overwrite this tab from Markdown” is not a preservation operation

The [`populate_from_markdown` implementation](https://github.com/taylorwilsdon/google_workspace_mcp/blob/54b1c56f7f9912ce32681460d7ca38f9c2a37564/gdocs/docs_tools.py#L2901) reads the tab end, deletes indices `1..end-1`, and inserts newly parsed content. In our native-table fixture it returns success and schedules the complete body deletion. It does not inspect whether the deleted body contains tables, chips, images or custom styles that the supplied Markdown cannot restore. A sibling tab is properly excluded by the emitted `tabId`; that is tab isolation, not preservation of the selected tab's contents.

The gdoc proposals are therefore valuable seeds for a Workspace regression suite, but they must not be counted as protections already present in gdoc 0.21.0. Likewise, a caller explicitly asking for a full replacement may intend to discard content; the missing protection matters for a read→edit Markdown→write workflow that assumes round-trip fidelity.

### Revision metadata is not a write precondition

Workspace's [batch manager](https://github.com/taylorwilsdon/google_workspace_mcp/blob/54b1c56f7f9912ce32681460d7ca38f9c2a37564/gdocs/managers/batch_operation_manager.py#L136) reads a revision before mutation and returns it in metadata. The captured batch contains only `requests`; it does not contain the revision. Thus a document read before resolving indices does not, by itself, prevent those indices becoming stale. Native phrase replacement avoids stale character positions by matching at execution time, but explicit coordinate edits and complete-tab rebuilds need separate consideration.

### The native Markdown writer is materially narrower than the reader

The Workspace [writer explicitly uses a CommonMark subset](https://github.com/taylorwilsdon/google_workspace_mcp/blob/54b1c56f7f9912ce32681460d7ca38f9c2a37564/gdocs/docs_markdown_writer.py#L1); GFM table/strike/task-list gaps are documented. Nested list flattening is stronger evidence of an implementation limitation because the input structure is parsed but indentation is discarded in emitted requests. Google derives bullet nesting from leading tab characters; the Workspace fixture emits none, while gdoc does. [Google's bullet request contract](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/request#CreateParagraphBulletsRequest)

These findings concern `manage_doc_tab(populate_from_markdown)`. Workspace's separate Drive Markdown-import route is a different renderer and was not tested by this probe. Do not transfer the native writer verdict to that route without testing it.

## Follow-ups suitable for upstream regression tests

1. Test every credential save against an existing loose-mode file; assert private mode afterwards and atomic replacement behavior.
2. Feed identical Markdown and native-rich bodies to rebuild commands; assert the chosen no-op/refusal contract before any destructive request.
3. Capture every read-dependent mutation's revision precondition; then run a live concurrent-edit fixture to establish end-to-end behavior.
4. Generate nested list trees and check both semantic output and UTF-16 ranges. A common Markdown parser is useful for the input AST; it is not itself proof that the Google request emitter preserves that AST.
5. Use injected transient GET failures and ambiguous write failures to distinguish recovered reads, safe refusal, and indeterminate mutations. Do not obtain reliability by blindly replaying writes.

The primary value of this audit is **transferring a failure family and its test**, not awarding a point because another app lacks the feature that failed.


## Controlled live list follow-up

The [native isolation test](live-list-oracle.json) replayed gdoc's exact text and paragraph-style requests. Its three per-item bullet requests flattened the list; replacing only those with one grouped bullet request restored `nestingLevel: 1` and 72-point child indentation. This identifies a concrete grouping interaction and fix direction, without claiming a gdoc patch has been applied. The offline leading-tab observer cannot certify final nesting.
